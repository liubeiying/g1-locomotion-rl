# 奖励函数与课程学习

我的做法：**每个奖励项都对应一个观察到的症状**，不堆权重，也不直接抄默认配置。

## 症状 → 奖励项

| 观察到的症状 | 我加的奖励 / 随机化项 | 验证到的效果 |
|---|---|---|
| 步态抖动、抬脚拖地 | 足底摆动高度奖励 + 落地接触力惩罚 | 待补 |
| 足底打滑、速度跟踪发散 | 足端滑移速度惩罚 + 摩擦系数域随机化 | 待补 |
| 动作输出跳变、真机打颤 | 动作变化率平滑惩罚 + 姿态正则 | 待补 |
| 只会走平地，遇地形就摔 | 课程学习：地形难度随进度爬升 | 待补 |
| 仿真完美、真机就废 | 质量 / 阻尼 / 延迟多维域随机化 | 待补 |

## 上游默认奖励权重（对照基线）

改奖励之前先看官方默认值，才知道自己改动的方向和量级。以下来自 `unitree_rl_gym` 的 `legged_gym/envs/g1/g1_config.py`：

| 奖励项 | 默认 scale | 说明 |
|---|---|---|
| tracking_lin_vel | 1.0 | 线速度跟踪，正向奖励 |
| feet_swing_height | -20.0 | 摆动腿离地高度，负向（惩罚） |
| base_height | -10.0 | 基座高度，负向 |
| dof_pos_limits | -5.0 | 关节接近限位的惩罚 |

同一份配置里还有几个会直接影响行为一致性的参数，我列在这里备查：

| 参数 | 默认值 | 来源 |
|---|---|---|
| 观测维度 | 47 | `g1_config.py` |
| 动作维度 | 12 | 同上 |
| critic 特权观测 | 50 | 同上 |
| 基座目标高度 | 0.78 m | 同上 |
| 初始位置 | [0, 0, 0.8] | 同上 |
| 控制类型 | P（位置控制） | 同上 |
| 刚度 Kp | 髋 100 / 膝 150 / 踝 40 | 同上 |
| 阻尼 Kd | 髋 2 / 膝 4 / 踝 2 | 同上 |

## 调参方法

1. **先看行为，再看曲线**：奖励曲线收敛不等于步态能用，我见过曲线很漂亮但走起来一塌糊涂的策略
2. **一次只改一个变量**：改一个奖励项就重新训练对比，否则无法归因
3. **抗扰测试定生死**：训练完做侧向推力和阶跃地形测试，看恢复能力

## 抗扰测试协议

| 测试 | 施加方式 | 观察指标 | 结果 |
|---|---|---|---|
| 侧向推力 | 待补 | 恢复步数、是否摔倒 | 待补 |
| 阶跃地形 | 待补 | 台阶通过率 | 待补 |

---

一点体会：奖励设计大概占了 sim-to-real 成败的一半。仿真里好看的步态，真机上未必能走，所以每一项奖励都要能在真机行为里找到对应的证据，否则就是过拟合到了仿真器的数值习惯上。
